# my-money-check-app
生活の資金繰りどうなってるかを確認するためのWebアプリ

三井住友銀行の口座明細と楽天カードの利用明細を、CSVの読み込み、またはNotionのデータベースからの取得で取り込み、月別・摘要別に整理・合算して表示します。
ユーザーが入稿したデータを表示するだけのアプリです。

- **CSVモード**: データはブラウザー内だけで処理されます。サーバーへの送信は行いません。
- **Notionモード**: トークンとデータベースのIDが、同じサイトの中継関数（`/api/notion/query`）を経由してNotionに送られます。サーバーには保存せず、ログにも出さない設計です（詳しくは「[プライバシー](#プライバシー)」）。

どちらのモードでも、取得したデータ（CSVの内容、Notionから取得した明細）は保存せず、ページを閉じるか再読み込みすると消えます（手入力した暫定支払いと、タグ・ルール・手動のタグ設定、データの取得元の選択のみ、後述のとおりこのブラウザーに保存されます）。

## 技術スタック

React + TypeScript（Vite、Vitest、Testing Library）。開発言語は TypeScript のみです。
Notionの取得には、ブラウザー側で TanStack Query（`@tanstack/react-query`）、中継関数で Notion の公式SDK（`@notionhq/client`）を使います。

## 使い方

```bash
npm install
npm run dev
```

表示されたURLをブラウザーで開き、CSVを選択またはドラッグ&ドロップします。UTF-8 と Shift_JIS に対応しています。銀行とカードは見出し行から自動判定します。
Notionのデータベースから読み込むときは、ページ上部の「データの取得元」で「Notionから取得」を選びます（[データソース](#データソースcsv--notion)を参照）。`npm run dev` でも、Notionの中継関数（`/api/notion/query`）が動きます。右上の「ヘルプ」から、CSVとNotionのデータ形式、Notionの設定手順、保存とプライバシーを確認できます。

### 対応するCSV

- 三井住友銀行: `年月日,お引出し,お預入れ,お取り扱い内容,残高,メモ,ラベル`（`メモ` と `ラベル` 以外が必須）
- 楽天カード: `"利用日","利用店名・商品名","利用者","支払方法","利用金額","手数料/利息","支払総額",…`（左の7列が必須。「◯月支払金額」など月によって変わる列は、支払い月の判定と暫定支払いの置き換えに使い、それ以外の列は無視します）

銀行かカードかは、見出し行の列名から自動で判定します。列の順番は問いません。

- 文字コード: UTF-8 と Shift_JIS（UTF-8として読めなければ Shift_JIS とみなします）。
- 日付: `2026/11/05`、`2026-11-05`、`2026.11.05`、`2026年11月5日`、`20261105`（全角も可）。
- 金額: 円の整数。カンマ区切りや「円」「¥」付きでも読み取れます。空欄は0円です。
- 読み飛ばし: 銀行の「お引出し」「お預入れ」が負の値の行、日付や金額を解釈できない行、列数が見出しと合わない行は読み飛ばし、読み込み結果に警告を出します。カードの負の金額は返金として扱います。

### 集計の考え方

- 銀行は「お引出し」を支出、「お預入れ」を収入として扱います。
- カードは「支払総額」を支出として扱います（空の場合は 利用金額＋手数料/利息）。
- 銀行からのカード引き落としとカード利用は二重計上になり得るため、銀行の支出とカードの支出は分けて表示します。合算した支出総額は参考値です。

### 暫定支払い（手入力）

楽天カードの今月の請求額のように、CSVにまだ含まれないが金額が分かっている支払いは、「暫定支払い（手入力）」から登録できます。支払い月、内容、金額、種別（カード/銀行/その他）、確定か見込みかを入力します。

- 暫定支払いは、概要の「支出合計（参考値）」と「収支（参考値）」、月別サマリーの「支出（参考値）」「収支（参考値）」に含まれます（確定・見込みの両方）。支出合計 ＝ 銀行の支出 ＋ カードの支出 ＋ 暫定支払い、収支 ＝ 収入合計 − 支出合計です。内訳は概要の「銀行の支出」「カードの支出」「暫定支払い」で確認できます。「銀行の支出」「カードの支出」と月別の同名の列はCSVの取引だけで、暫定支払いは混ぜません。月別サマリーの「暫定支払い（手入力）」列は、その月の確定・見込みの内訳です。
- 摘要別の支出ランキングはCSVの取引だけが対象で、暫定支払いは含みません。
- 月の絞り込みは暫定支払いにも適用されます。キーワードで絞り込んでいる間は、内容・メモに一致した暫定支払いだけが支出合計・収支に含まれます（銀行／カードのソース絞り込みは暫定支払いには適用されません）。
- カードの暫定支払いと、銀行からのカード引き落としは同じ支出を二重に数えることがあります。その場合は、どちらかを削除するか置き換えてください。
- 入力した暫定支払いだけは、このブラウザーのlocalStorageに保存され、再読み込みしても残ります。CSVの内容は保存しません。
- 同じ支払いを含むCSVを読み込むと、CSVのデータが暫定値を置き換えます。一覧には「CSVで置き換え済み」と表示され、入力データは消えないので、CSVを削除すると暫定値がそのまま集計に戻ります。支出合計・収支には、カード・銀行のどちらも、置き換えた分を**加算しません**（元のCSVの取引がすでに「カードの支出」「銀行の支出」に入っているため。二重計上を避けます）。
  - カード: 楽天カードCSVの見出し「◯月支払金額」と利用日から支払い月を判定し、同じ支払い月のカードCSVが読み込まれると置き換えます。暫定値は削除せず、**CSVの「◯月支払金額」列の合計（その月に実際に支払う金額。分割払いなどで支払総額の合計と異なることがあります）で上書き**します。カードCSVの取引は利用月（例: 10月）の行に入りますが、暫定支払いは支払い月（例: 11月）の行に入るため、暫定値を単に外すと支払い月の行が消えてしまうからです。上書き後も、月別サマリーと月フィルタには支払い月の行が残り、確定額として「CSV確定 ○円」と表示されます（表示のみで、支出・収支には加算しません）。一覧には「CSVの支払額: ○円（暫定: ○円、差額 ±○円）」が表示されます。CSVの金額は保存しません（保存されるのは入力した暫定値だけです）。
  - 銀行: 暫定支払いの月の取引を含む銀行CSVが読み込まれると置き換えます。その月の取引はCSVに実在するので、暫定値は集計（支出合計・収支を含む）から外れます。
  - 種別「その他」は置き換えません。
  - 「CSVがあっても暫定値を使う」を選ぶと、その項目は置き換えません。CSVが部分的な期間しか含まない場合などに使います。

### タグ付け

どの明細が家賃なのか、どれがサブスクなのかを確認できるように、明細にタグ（ラベル）を付けられます。タグは1つの明細に複数付けられます。「タグとルール」から、タグ（名前と色）の追加・名前と色の変更・削除ができます。「おすすめのタグを追加」で、家賃・サブスク・光熱費などをまとめて追加できます。CSVを読み込んでいなくても使えます。

タグは次の2つの方法で付きます。

- **ルール（自動）**: 「摘要に ◯◯ を含む明細に ▲▲ を付ける」というルールを登録すると、摘要（暫定支払いは支払先・内容）にその文字列を含む明細へ自動でタグが付きます。全角・半角と大文字・小文字は区別しません。ルール入力中に、いま読み込んでいる明細のうち何件が該当するかを確認できます。
- **手動の上書き**: 明細（と暫定支払い）の行の「タグを編集」から、その明細に付けるタグを選んで保存します。手動で設定した明細は、ルールより手動の設定が優先されます。「ルールに戻す」で手動の設定を消し、ルールの結果に戻せます。編集の中の「この摘要をルールにする」は、選んだタグ1つに対して、その行の摘要をキーワードにしたルールを追加します。手動の設定は、日付・摘要・金額が同じ明細にまとめて適用されます。

保存範囲: タグ・ルール・手動の設定だけが、このブラウザーのlocalStorageに保存されます（CSVの内容は保存しません）。手動の設定は「どの明細か」を区別するために、その明細の取引元・日付・摘要・金額から作ったハッシュ値（元の内容は復元できない短い文字列）だけを保存します。日付・摘要・金額そのものは保存しません。ただし、ルールのキーワードはあなたが入力した文字列がそのまま保存されます（「この摘要をルールにする」を使うと、その行の摘要がキーワードとして保存されます）。CSVを読み込み直すと、保存済みのルールと手動の設定がそのまま適用されます。

絞り込みと集計:

- 「絞り込み」の「タグ」で、タグ（複数選択可。選んだタグのいずれかが付いた明細）と「タグなし」で絞り込めます。絞り込んだ結果は、概要・月別サマリー・摘要別ランキング・残高推移・明細のすべてに反映され、暫定支払いにも同じ条件が適用されます（残高推移は、キーワードでは絞り込まない従来の動作のままです）。「条件をリセット」でタグの選択も外れます。削除したタグは選択から自動で外れます。
- 「タグ別の支出」では、絞り込み後の支出を、タグごとの金額・件数・支出合計に対する割合の横棒で確認できます（「タグなし」の行もあります）。タグ名を押すと、そのタグで絞り込めます。
- **注意**: 複数のタグが付いた明細は、各タグに全額を計上します。そのため、タグ別の合計が支出合計を超えることがあります。集計の対象は、概要の「支出合計」と同じく、CSVの取引（支出）と暫定支払いです。CSVの支払額で上書きされた暫定支払いは、CSVの利用明細と二重になるため含めません。

## データソース（CSV / Notion）

ページ上部の「データの取得元」で、「CSVを読み込む」と「Notionから取得」を切り替えられます。既定はCSVです。選択はこのブラウザーのlocalStorage（`my-money-check:data-source:v1`）に保存されます。

- 切り替えても、もう一方で読み込んだデータは破棄しません。CSVを読み込んだ状態でNotionに切り替えて戻っても、CSVはそのまま残ります。
- 集計（概要・月別サマリー・摘要別ランキング・残高推移・明細・タグ別の支出）、暫定支払いの置き換え、タグ付けは、選んでいる取得元のデータに対して動きます。Notionのデータは、取得時にCSVと同じ形に変換してから使います。
- アプリ内の「ヘルプ」にも、同じ内容を載せています。

### Notionのデータ形式

銀行用とカード用のデータベースを別々に用意します。どちらか片方だけでも読み込めます。プロパティ名は下の表のとおりにしてください（タイトル型のプロパティだけは、名前が自由です。推奨名を表に載せています）。CSVの列と同じ名前なので、SMBCのCSVなどをNotionにインポートして、各プロパティの型を直せば使えます。

この表は、アプリ内ヘルプの表と同じ定義（`src/lib/notion/schema.ts`）から作っています。

| --- | --- | --- | --- | --- | --- | --- |

| `利用日` | 日付 | 必須 | `date`（日付）、`formula`（数式） | `利用日` | カードを利用した日。 | `2026-11-03` |
| `利用金額` | 数値 | 必須 | `number`（数値）、`formula`（数式）、`rollup`（ロールアップ） | `利用金額` | 利用金額（円の整数）。返金は負の値にします。 | `3980` |
| `手数料/利息` | 数値 | 任意 | `number`（数値）、`formula`（数式）、`rollup`（ロールアップ） | `手数料/利息` | 分割・リボ払いの手数料や利息（円の整数）。空欄は0として扱います。 | `120` |

| `支払方法` | テキスト | 任意 | `rich_text`（テキスト）、`select`（セレクト）、`multi_select`（マルチセレクト）、`status`（ステータス）、`url`（URL）、`email`（メール）、`phone_number`（電話番号）、`formula`（数式）、`title`（タイトル） | `支払方法` | 支払方法（1回払い・分割など）。 | `1回` |
| `支払い月` | テキストまたは日付 | 任意 | `rich_text`（テキスト）、`select`（セレクト）、`multi_select`（マルチセレクト）、`status`（ステータス）、`url`（URL）、`email`（メール）、`phone_number`（電話番号）、`formula`（数式）、`title`（タイトル）、`date`（日付） | ― | その明細を請求・支払う月。「2026-11」「2026/11」「2026年11月」のテキスト、または日付（年月の部分を使います）。支払い月ごとに別のファイルとして取り込みます。 | `2026-11` |
| `今回支払金額` | 数値 | 任意 | `number`（数値）、`formula`（数式）、`rollup`（ロールアップ） | `◯月支払金額` | その明細について、支払い月に実際に支払う金額（円の整数）。分割払いでは支払総額と異なります。支払い月ごとの合計が、暫定の支払い予定の置き換えに使われます。 | `2050` |

共通のルール:

- 金額は整数の円です。
- 銀行の「お引出し」「お預入れ」が負の値の行、小数の行、日付を解釈できない行は読み飛ばし、取得結果に警告を出します。
- 許容する型は、数値が `number` / `formula`（結果が数値）/ `rollup`（結果が数値）、日付が `date` / `formula`（結果が日付）、テキストが `rich_text` / `select` / `multi_select` / `status` / `url` / `email` / `phone_number` / `formula`（結果が文字列）です。
- カードの「支払い月」は、`2026-11`、`2026/11`、`2026年11月` のテキスト、または日付（年月の部分を使います）です。
- カードの「支払い月」と「今回支払金額」（楽天カードCSVの「◯月支払金額」列に相当）の両方があると、その支払い月の暫定支払い（カード）を、Notionの金額で上書きできます。どちらかが無いと、暫定値の置き換えは起きません。
- 1つのデータベースで読み込める行数は最大20,000行です。

### Notionの設定手順

1. **インテグレーションを作る**: [Notionのインテグレーションの管理ページ](https://www.notion.so/profile/integrations)で、新しいインテグレーション（種類は「内部」）を作ります。必要な権限は「コンテンツを読み取る」だけです。
2. **トークンを取得する**: インテグレーションの「シークレット」（トークン）をコピーします。
3. **データベースをインテグレーションに共有する**: 銀行・カードそれぞれのデータベースのページで、右上の「…」メニューの「接続」から、作成したインテグレーションを追加します。共有していないデータベースは読み取れません（「見つかりません」と表示されます）。
4. **データベースのURLを取得する**: データベースをページいっぱいに開き、「リンクをコピー」でURLをコピーします。32桁のIDでも構いません。
5. **アプリに入力する**: 「Notionから取得」でトークンと、銀行・カードのデータベースのURL（またはID）を入力し、「Notionから読み込む」を押します。形式が合わないときは、不足しているプロパティや型の違いが一覧で表示されます。

CSVをNotionにインポートして使う場合:

1. Notionの「インポート」から「CSV」を選び、銀行またはカードのCSVを取り込みます。文字化けするときは、CSVをUTF-8に変換してから取り込んでください。
2. 取り込まれたデータベースの各プロパティの型を直します。日付の列（「年月日」「利用日」）は「日付」、金額の列（「お引出し」「お預入れ」「残高」「利用金額」「手数料/利息」「支払総額」）は「数値」にします。「利用者」「支払方法」「メモ」「ラベル」はテキストのままで構いません。
3. 暫定支払いをNotionの金額で置き換えたいときは、カードのデータベースに「支払い月」と「今回支払金額」を追加します。
4. 上の手順3〜5のとおり、データベースをインテグレーションに共有して、URLをアプリに入力します。

画面の名称はNotionの更新で変わることがあります。

### 構成

```
ブラウザー ── POST /api/notion/query ──▶ 中継関数 ──▶ Notion API
                 （x-notion-token ヘッダーでトークンを渡す）
```

- ブラウザーはNotion APIを直接呼ばず、同じサイトの中継関数 `/api/notion/query` を呼びます。本番ではVercelの関数（`api/notion/query.ts`）、`npm run dev` と `npm run preview` ではViteのミドルウェアが同じ処理を受け持ちます。
- 中継関数は、指定されたデータベースを読み取って返すだけです（書き込みはしません）。データベースの全行を、ページ送りしながらブラウザーが取得します。
- ブラウザー側では、Notionの行を、CSVを読み込んだときと同じ形（`ParsedFile`）に変換してから使います。取得にはTanStack Queryを使い、ウィンドウのフォーカスや再接続での自動再取得はしません。「再読み込み」を押したときだけ取得し直します。

### トークンの扱い

- トークンはサーバーに保存しません。読み込みのたびに、リクエストの `x-notion-token` ヘッダーで中継関数に渡し、Notionへの問い合わせにだけ使います。URLやリクエストの本文には入れません。ログにも出しません。
- ブラウザーでの保存先は、既定ではこのタブの中だけ（sessionStorage）です。タブを閉じると消えます。「このブラウザに保存する」をオンにすると、localStorageに保存され、次回以降も入力せずに使えます。共有のパソコンではオンにしないでください。「トークンを削除」で、どちらからも消せます。
- データベースのURL・IDの入力欄の内容と、「このブラウザに保存する」の選択は、localStorageに保存されます。

### デプロイ時の注意

Notionモードには、中継関数（サーバー側の実行環境）が必要です。Vercelにデプロイすると、`api/` ディレクトリの関数が自動で動きます（サーバー側の環境変数は不要です）。GitHub Pagesのような静的ホスティングだけでは、Notionモードは使えません（CSVモードは使えます）。

## プライバシー

- **CSVモード**: CSVのデータは、ブラウザーの中だけで処理されます。サーバーへの送信も、保存もしません。
- **Notionモード**: トークンとデータベースのIDは、同じサイトの中継関数を経由してNotionに送られ、取得した明細もその関数を通ってブラウザーに届きます。中継関数はトークンやデータを保存せず、ログにも出さない設計です。ただし、データがサーバーを経由する点はCSVモードと異なります。気になる場合は、CSVモードを使ってください。
- どちらのモードでも、取得した明細そのもの（日付・摘要・金額）はこのブラウザーに保存しません。保存されるのは、手入力した暫定支払い、タグ・ルール・手動のタグ設定、データの取得元の選択、Notionの設定（データベースのURL・IDと保存オプション。トークンは上記のとおり）です。
